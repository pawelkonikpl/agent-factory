# API email log: `emails` model, migration, filtered list, SQL stats and single-email endpoints

> Feature: Add the email log to the API: the `emails` model with its subject and body snapshot, the migration, the filtered paginated list, SQL stats, and the single-email read, update, mark and delete endpoints, as specified in `specs/email-sender/backend.md` API-10 (covers B9 without resend)

## Context

This is roadmap item API-10 of Phase 4 (Email Sender API). The source of truth is
`specs/email-sender/backend.md`, "API-10: The email log" (Requirements, Pitfalls, Acceptance
criteria), plus that file's "Rules for every item". The wire format is in
`specs/email-sender/api-contract.md` §0 (conventions, errors, pagination, trailing slashes, the
`200 {"message"}` exception for `DELETE /emails/{id}`), §1 (`EmailStatus`, "`delivered` is not a
status"), §2 (`EmailSchema`, `EmailUpdateSchema`, `EmailStatsSchema`, `MessageSchema`,
`Page<T>`) and §3.4 (the emails endpoints). Background in `specs/email-sender/README.md` §5/§6
(layer rules, soft delete, `PrincipalDep` everywhere, `selectin`, no bare dicts between layers),
W-08 (server-side `search`), W-09 (`total`, stats from `/emails/stats/`, no `delivered` status),
W-17 and D25 (subject/body snapshot), D27 (by-campaign and by-client lists stay plain arrays with
`skip`/`limit`), D28 (page size). This spec restates the backend.md section; where they differ,
this spec wins.

`POST /emails/{id}/resend` is API-13 and out of this item. Nothing in the app writes `Email`
rows until API-11; in this item rows are created only through the repository (tests).

What API-2 to API-9 left in `api/` (specs `specs/features/010-` to `018-*.md`):

- `app/models/base.py`: `Base` with `NAMING_CONVENTION`, `IdMixin`, `TimestampMixin`,
  `SoftDeleteMixin` (Python-side defaults only) and `utc_now()`. `app/models/__init__.py`
  imports every model and lists it in `__all__`; Alembic sees only the tables imported there.
- `app/models/campaign.py` is the pattern for an enum column: `CampaignStatus(enum.StrEnum)`,
  `Enum(<enum>, native_enum=False, values_callable=_values, create_constraint=True,
  name="campaign_status")`. `_values` is a private helper in that module.
- The campaigns area is the pattern to copy: `app/repositories/campaign_repository.py`
  (`_list_filters(...)` shared by `get_all` and `count`, `icontains(term, autoescape=True)`,
  order `created_at desc, id desc`, each write commits), `app/services/campaign_service.py`
  (only domain errors, no `sqlalchemy` import, `to_schema`, `_rate` rounding to 2 decimals with
  0.0 for a zero denominator), `app/api/campaigns.py` (`APIRouter(prefix=..., tags=[...])`,
  `PrincipalDep` plus a `...ServiceDep` on each endpoint, no `try`/`except`),
  `get_campaign_service`/`CampaignServiceDep` in `app/dependencies.py`, and
  `app.include_router(...)` in `create_app` (`app/main.py`).
- `app/schemas/base.py`: `BaseSchema`, `Page[T]`, the frozen dataclass `PageParams` with
  `Query(...)` fields exposed as `PageParamsDep = Annotated[PageParams, Depends()]`, and
  `MessageSchema` (already used by `app/api/config.py`).
- `app/errors.py`: `NotFoundError` (404) and `BusinessRuleError` (400), mapped by the one
  handler in `app/main.py`.
- Sessions use `expire_on_commit=False`; a relationship never loaded cannot be lazy-loaded in
  async code (`MissingGreenlet`), so a new `Email` must be given its `Campaign` and `Client`
  objects, not only IDs, when its `campaign`/`client` are read afterwards in the same session.
- Migrations: the head is `4a109566473f` (`migrations/versions/4a109566473f_add_campaigns.py`).
- Tests: `tests/test_campaigns_schemas.py`, `test_campaigns_service.py`,
  `test_campaigns_api.py` are the style to follow (fixtures `session_factory`, `client`,
  `bearer`; 401 parametrized over every endpoint; exact `detail` asserts).

## Requirements

1. **Model**, new module `app/models/email.py` (`Mapped[]`/`mapped_column` style):
   - `EmailStatus(enum.StrEnum)` with `PENDING`, `SENDING`, `SENT`, `FAILED`, `BOUNCED`,
     `REJECTED`, `DEFERRED` (lowercase values).
   - `Email(IdMixin, TimestampMixin, SoftDeleteMixin, Base)`, table `emails`:
     `campaign_id` `ForeignKey("campaigns.id", ondelete="CASCADE")` NOT NULL, `index=True`;
     `client_id` `ForeignKey("clients.id", ondelete="CASCADE")` NOT NULL, `index=True`;
     `recipient_email` `String(256)` NOT NULL, `index=True`; `subject` `String(500)` NOT NULL;
     `body` `Text` NOT NULL; `status` NOT NULL, Python-side `default=EmailStatus.PENDING`,
     `index=True`, as `Enum(EmailStatus, native_enum=False, values_callable=enum_values,
     create_constraint=True, name="email_status")`; `sent_at` (`index=True`), `delivered_at`,
     `opened_at`, `clicked_at`, `bounced_at`, all `DateTime(timezone=True)` NULL;
     `error_message` `Text` NULL; `error_code` `String(50)` NULL; `retry_count` int NOT NULL
     default 0; `max_retries` int NOT NULL default 3; `smtp_message_id` `String(255)` NULL;
     `smtp_response` `Text` NULL. No server defaults.
   - Relationships `campaign: Mapped[Campaign]` and `client: Mapped[Client]`, both
     `lazy="selectin"`, without back-references: `app/models/campaign.py`'s tables and
     `app/models/client.py` do not change.
   - The enum values helper is not duplicated: move `_values` from `app/models/campaign.py` to
     `app/models/base.py` as a public `enum_values` and use it in both modules (the campaign
     columns stay the same, so `alembic check` shows no drift).
   - `app/models/__init__.py` also imports `Email` and `EmailStatus` and lists them in
     `__all__`.
2. **Migration.** One new revision, generated in `api/` with
   `uv run alembic revision --autogenerate -m "add emails"` against `emailsender_test` at
   `4a109566473f`, then corrected by hand: `down_revision` is `'4a109566473f'`; `upgrade()`
   creates the table and the six indexes listed in the Context; the two explicit
   `sa.CheckConstraint` lines are removed (the CHECK comes only from the `sa.Enum(...,
   create_constraint=True)` column); `downgrade()` drops the indexes and the table; long lines
   are wrapped so `uv run ruff check .` passes with no `# noqa`. Existing revisions and
   `migrations/script.py.mako` do not change.
3. **Schemas**, new module `app/schemas/emails.py`, all inheriting `BaseSchema`:
   - `EmailSchema` with exactly the contract keys: `id`, `campaign_id`, `client_id`,
     `recipient_email`, `client_name: str | None`, `campaign_name: str | None`, `subject`,
     `content`, `status: EmailStatus`, `sent_at`, `delivered_at`, `opened_at`, `clicked_at`,
     `bounced_at` (`datetime | None`), `error_message`, `error_code` (`str | None`),
     `retry_count: int`, `max_retries: int`, `smtp_message_id`, `smtp_response`
     (`str | None`), `created_at`, `updated_at`. `status` dumps as the lowercase value.
   - `EmailUpdateSchema`, every field optional with default `None`: `status: str | None` (a
     plain string; the service validates it), `sent_at`, `delivered_at`, `opened_at`,
     `clicked_at`, `bounced_at` (`datetime | None`), `error_message: str | None`,
     `error_code: str | None` with `max_length=50`, `smtp_message_id: str | None` with
     `max_length=255`, `smtp_response: str | None`.
   - `EmailStatsSchema`: `total`, `pending`, `sending`, `sent`, `failed`, `bounced`,
     `rejected`, `deferred`, `delivered`, `opened`, `clicked` (`int`), and `delivery_rate`,
     `open_rate`, `click_rate`, `bounce_rate` (`float`).
   - `EmailFilters`, a frozen dataclass of `Query(...)` fields in the `PageParams` style, with
     `EmailFiltersDep = Annotated[EmailFilters, Depends()]`: `campaign_id: int | None`,
     `client_id: int | None`, `status: EmailStatus | None` (so `status=unknown` answers 422),
     `from_date: datetime | None`, `to_date: datetime | None`, `has_error: bool | None`,
     `search: str | None`, all defaulting to `None`. This is the one object passed from the
     router through the service to the repository.
4. **Repository**: `EmailRepository` in `app/repositories/email_repository.py`, built with an
   `AsyncSession`, owning every SQLAlchemy query for emails. Every read skips soft-deleted
   emails; every list orders by `created_at desc, id desc`.
   - `create(*, campaign: Campaign, client: Client, recipient_email: str, subject: str,
     body: str)`: a new `pending` email with the `Campaign` and `Client` objects set; commits.
   - `get_by_id(email_id)`: the non-deleted email or `None`.
   - `get_all(filters, skip, limit)` and `count(filters)`: one shared `_list_filters(filters)`.
     `campaign_id`, `client_id`, `status` are equality filters; `from_date` →
     `created_at >= from_date`, `to_date` → `created_at <= to_date`; `has_error` true →
     `error_message IS NOT NULL`, false → `IS NULL`; `search` (ignored when `None` or `""`) →
     `recipient_email`, `subject`, the client's `company_name` or the campaign's `name`
     contains it case-insensitively with `icontains(term, autoescape=True)` (for the related
     names use `Email.client.has(...)`/`Email.campaign.has(...)` or a join; each email is
     returned once). `count` applies the same filters without `skip`/`limit`.
   - `get_by_campaign(campaign_id, skip, limit)`, `get_by_client(client_id, skip, limit)`,
     `get_failed(campaign_id: int | None)` (`status = failed`, optionally by campaign, not
     paginated).
   - `get_for_recipient(campaign_id, client_id)`: the newest non-deleted email of that pair, or
     `None` (for API-11; tested here).
   - `update(email, data: EmailUpdateSchema, status: EmailStatus | None)`: writes `status`
     when given and every other field of `data` that is not `None`; commits.
   - `soft_delete(email)`, `mark_opened(email)`, `mark_clicked(email)` (`opened_at` /
     `clicked_at` = `utc_now()`, overwriting an earlier value; status unchanged); each commits
     and returns the email.
   - `get_stats(campaign_id: int | None)`: **one SQL query** over non-deleted emails
     (filtered by campaign when given) with `func.count()` and
     `func.count().filter(<condition>)` (PostgreSQL `COUNT(*) FILTER (WHERE …)`): `total`, one
     count per status, `delivered` (`delivered_at IS NOT NULL`), `opened` (`opened_at IS NOT
     NULL`), `clicked` (`clicked_at IS NOT NULL`). It never loads `Email` rows. It returns the
     counts as a typed object (a dataclass or the schema), not a dict.
5. **Service**: `EmailService` in `app/services/email_service.py`, built with an
   `EmailRepository`, raising only domain errors and importing nothing from `sqlalchemy`:
   - `get_all(filters, skip, limit) -> Page[EmailSchema]`; `get_by_campaign`,
     `get_by_client`, `get_failed` → `list[EmailSchema]`.
   - `get_by_id(email_id)`: `NotFoundError(f"Email {email_id} not found")` when missing or
     soft-deleted.
   - `update(email_id, data)`: `get_by_id` (404); then, when `data.status` is given and is not
     an `EmailStatus` value, `BusinessRuleError(f"Invalid email status: {value}")` with nothing
     written; else `update` with the parsed status.
   - `delete(email_id)`, `mark_opened(email_id)`, `mark_clicked(email_id)`: `get_by_id` (404),
     then the repository call.
   - `get_stats(campaign_id) -> EmailStatsSchema`: the repository counts plus the rates
     `delivery_rate = delivered/total`, `open_rate = opened/sent`, `click_rate = clicked/sent`,
     `bounce_rate = bounced/total`, each `* 100` rounded to 2 decimals, `0.0` when the
     denominator is 0 (the same formula as `_rate` in `campaign_service.py`).
   - `to_schema(email) -> EmailSchema`: `status` value; `client_name` = the client's
     `company_name`; `campaign_name` = the campaign's `name`; `subject` = `email.subject` and
     `content` = `email.body` (the snapshot, never the campaign's current text).
6. **Wiring** in `app/dependencies.py`: `get_email_service(session: SessionDep)` returns
   `EmailService(EmailRepository(session))`, and `EmailServiceDep`. Nothing added to
   `Container`.
7. **Router**: `app/api/emails.py`, `APIRouter(prefix="/emails", tags=["Emails"])`, included in
   `create_app` after the campaigns router. Every endpoint takes `PrincipalDep` and
   `EmailServiceDep` and only does HTTP. Registered in this order, so the fixed paths come
   before `/{email_id}`:
   - `GET /emails/` with `EmailFiltersDep` and `PageParamsDep` → `200 Page[EmailSchema]`;
   - `GET /emails/stats/` with `campaign_id: int | None = None` → `200 EmailStatsSchema`;
   - `GET /emails/failed/` with `campaign_id: int | None = None` → `200 list[EmailSchema]`;
   - `GET /emails/campaign/{campaign_id}` with `PageParamsDep` → `200 list[EmailSchema]`;
   - `GET /emails/client/{client_id}` with `PageParamsDep` → `200 list[EmailSchema]`;
   - `GET /emails/{email_id}` → `200 EmailSchema`;
   - `PUT /emails/{email_id}`, body `EmailUpdateSchema` → `200 EmailSchema`;
   - `POST /emails/{email_id}/mark-opened` and `POST /emails/{email_id}/mark-clicked`, no body

   - `DELETE /emails/{email_id}` → `200 MessageSchema` `{"message": "Email deleted

   No `resend` route, and the paths are exactly these (trailing slashes as listed).

## Assumptions

- `EmailRepository.create` takes the `Campaign` and `Client` objects, not IDs as backend.md
  implies. Reason: `to_schema` reads their names, and an unloaded relationship raises
  `MissingGreenlet`; 018 made the same choice for recipients.
- `status` on `GET /emails/` is typed `EmailStatus` (422), while `status` in the `PUT` body is a
  plain string checked by the service (400 "Invalid email status: …"). Reason: that is what the
  contract says for each.
- The status check is case-sensitive (`"SENT"` is invalid), and 404 is checked before it.
  Reason: wire values are lowercase; a missing email is reported first.
- `from_date` and `to_date` are inclusive (`>=`, `<=`), and a naive date counts as UTC. Reason:
  the contract names no bounds; asyncpg stores naive datetimes as UTC.
- `null` in `PUT /emails/{id}` means "don't change", so no field can be cleared through it.
  Reason: the contract says so.
- `errorCode` over 50 and `smtpMessageId` over 255 characters answer 422. Reason: the columns
  are that long, and a database error would be a 500.
- Marking opened or clicked again overwrites the time with now, and does not change `status`.
  Reason: the contract says "set to now" and names no status change.
- Emails of a soft-deleted campaign or client stay in the log, with `clientName` and
  `campaignName` still filled in; those fields are never `null` in practice. Reason: the FKs are
  NOT NULL and soft-deleting a campaign or client does not touch `emails`.
- An unknown `campaign_id`/`client_id` on the stats, failed, by-campaign and by-client endpoints
  answers 200 with zeros or `[]`, not 404. Reason: they are filters over the log, and the
  contract lists no 404 for them.
- `get_for_recipient` returns the newest row of the pair. Reason: one row per pair is API-11's
  rule; newest is a safe pick if several exist.
- `_values` moves to `app/models/base.py` as `enum_values`. Reason: a second enum model would
  otherwise import a private name or duplicate it.
- Path IDs outside int32 and NUL bytes end in a 500, as in the other areas. Reason: 012's known
  behaviour; fixing it for one area alone would make them differ. A security decision for a
  human.
